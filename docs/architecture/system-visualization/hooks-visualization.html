01 · The pipeline

107 hooks woven through
every Claude session.

A hook is a small TypeScript program that Claude Code runs at a fixed point in the session lifecycle. There are 7 events — from SessionStart to SessionEnd — and 107 hooks distributed across them. The overwhelming majority inject context; only 5 in PreToolUse can deny a tool call outright.

Counts reflect registered hook entries in settings.json plus event handlers in .claude/hooks/src/. PostToolUse dominates: it is where context injection, extraction, and the Braintrust scoring emits live.

Inject vs block. Roughly 95% of hooks only read the event and return context or a no-op. They never stop you. The exception is the PreToolUse guard layer — and even there, only 5 hooks return permissionDecision: deny: package-install-guard, plan-to-ralph-enforcer, ralph-delegation-enforcer, tldr-read-enforcer, and smart-search-router. Everything else either suggests or injects.

What hooks do for you

  • Inject memory matches before Claude reads your prompt
  • Suggest the right agent / skill for the task
  • Block supply-chain-risky package installs
  • Type-check files immediately after every edit
  • Save continuity state before context compaction
  • Emit Braintrust scores so the system grades itself

02 · Boot

What fires the moment a
session opens.

SessionStart runs 10 hooks. They check Docker, register the session in PostgreSQL, load the continuity ledger, validate the knowledge tree, resume any in-flight Ralph loop, and warm the memory + TLDR caches. Order matters: the session must be registered before continuity is loaded, and the BGE embedding daemon is spawned fire-and-forget so the first prompt benefits.

Boot sequence (left → right)
1

session-start-docker

Confirms the PostgreSQL container is reachable. Everything downstream that touches coordination or memory depends on it.

session-start-docker.ts
2

session-register

Writes a row to the sessions table for cross-terminal awareness. Other terminals can now see this session and its working_on field.

session-register.ts
3

session-start-continuity + init-check

Loads the handoff/continuity ledger and validates knowledge-tree.json. If the tree is missing or empty it auto-regenerates (for projects with code files).

session-start-continuity.ts · session-start-init-check.ts
4

session-start-recovery

Detects an in-flight Ralph loop via .ralph/state.json and resumes it, surfacing the active task back into context.

session-start-recovery.ts
5

memory cache warmer

session-start-memory-loaders primes recall. The BGE embedding daemon is spawned fire-and-forget here so prompt #1 hits a warm daemon.

session-start-memory-loaders.ts
6

hook-health-monitor

Audits that every registered hook's dist/*.mjs exists and isn't stale (src newer than dist). Stays quiet when healthy; reports fix commands when not. Also emits the hook_health_ratio Braintrust score once per boot.

hook-health-monitor.ts

03 · Per-turn

The prompt is intercepted
before Claude sees it.

12 hooks fire on UserPromptSubmit. The headliner is memory-awareness: it pulls intent out of your prompt, probes the BGE daemon, runs hybrid RRF recall, and injects a MEMORY MATCH block. Alongside it, skill-activation-prompt matches keywords + intent to suggest skills, and the Ralph/Maestro state hooks inject progress and retry context.

Prompt → recall → inject

memory-awareness flow

  1. Extract intent via shared/intent-extractor (strip "can you", "help me", recall keywords)
  2. Probe BGE daemon at $TEMP/ccv3-embedding.json (200ms budget)
  3. Daemon ready → hybrid RRF; not ready → --text-only + fire-and-forget spawn for next time
  4. Run local-memory + DB-memory in parallel, merge & dedupe
  5. Apply a mode-aware floor; survivors become MEMORY MATCH
  6. Log every fire to memory-recall.jsonl and emit the recall Braintrust score

04 · The guard layer

20 hooks stand between you
and every tool call.

PreToolUse is the only event that can deny. 20 hooks fire here — most suggest (route Grep to AST-grep, route Explore to scout, suggest agents) but 5 can block. The flagship is package-install-guard: a 4-layer supply-chain check that intercepts every pip install / npm i before it runs.

05 · After the fact

Braintrust scoring emit sites

3 of 4 emitters live on PostToolUse. Each calls await emitBraintrustScore(payload) — fail-open, 2s timeout, silent when TRACE_TO_BRAINTRUST != "true".

The emit invariant. All 4 score sites must use await emitBraintrustScore(...) — the await matters. A known regression silently reverted three of them to void emitBraintrustScore(...). The guard scripts/audit-braintrust-emits.sh now requires the await form and must be re-run after any TS hook edit. (See hook-dev-lifecycle.md failure modes.)

06 · Boundary

Saving state before the
context window collapses.

When the context window fills and Claude Code is about to compact, PreCompact fires 2 hooks. Their entire job is survival: snapshot the continuity ledger and extract any pending learnings before the conversation is compressed and detail is lost. This is what lets Ralph loops survive /compact.

Context filling → snapshot + extract
1

pre-compact-continuity

Writes a snapshot of the continuity ledger and any active handoff to a YAML file. On the next prompt after compaction, session-start-continuity reads it back so nothing is lost.

pre-compact-continuity.ts
2

pre-compact-extract

The L1 layer of the self-improvement loop. Pulls insights out of the about-to-be-compressed conversation and stores them in archival_memory before they vanish.

pre-compact-extract.ts
Ralph compaction survival. Because these two hooks run automatically, running /compact mid-Ralph is safe — the loop state is persisted to a hook-managed YAML handoff and resumed by session-start-recovery after the window clears.

07 · Boundary

Cleanup, extraction, and the
session's final score.

Two events close the loop. SubagentStop fires when a delegated agent finishes — saving its results back into continuity. SessionEnd runs 4 hooks: cleanup, learning extraction (L2), outcome marking, and handoff indexing. The session-end scoring path is where the system records its final self-assessment.

SubagentStop

Fires when a Task-spawned agent completes. Persists agent output into the continuity ledger so the orchestrator's next turn sees the result even after context churn.

agent-error-capture agent-verification

Companion PostToolUse:Task hooks (agent-error-capture, agent-verification, ralph-monitor) detect failures and verify claims as agents return.

Insights are captured at three depths: live during tool use (L0, quality-gated), before compression (L1), and at session close (L2). Each layer feeds the same archival_memory store that memory-awareness reads on the next session's prompt.

session-end scoring. The hook_health_ratio Braintrust score is emitted by hook-health-monitor at boot, but the session-end hooks finalize the outcome record — closing the observability loop so Braintrust can grade how the whole session went. SessionEnd hooks return {} (side-effect only) and must use fire-and-forget spawn for long work to avoid the "Hook cancelled" timeout.

08 · Under the hooks

The reusable layer beneath
all 107 hooks.

Hooks are thin. The real work lives in .claude/hooks/src/shared/ — a set of modules every hook imports. Braintrust emission, BGE embeddings over TCP, intent extraction, session isolation, and Postgres coordination are all written once here and reused everywhere.

shared/braintrust-score.ts

Score (feedback) emission from TS hooks. Fail-open: never throws. Skips when TRACE_TO_BRAINTRUST != "true" or no API key. 2s AbortController timeout.

await emitBraintrustScore({ spanId, scores: { hook_health_ratio: 0.96 }, metadata: { ... }, }); // POST /v1/project_logs/{id}/feedback

shared/embedding-client.ts

Talks to the long-lived BGE-large daemon over TCP loopback. 4-byte big-endian length prefix + JSON. Discovers the daemon via $TEMP/ccv3-embedding.json; absence → text-only fallback.

// commands { cmd: "ping" } -> { ok, ready, dim: 1024 } { cmd: "embed", text } -> { vector[1024] } { cmd: "embed_batch", texts }

shared/intent-extractor.ts

Pulls the what out of a prompt: strips meta-language ("can you", "help me", "recall") and stop-words, with keyword fallback for short prompts. Used by agent-recall-injector and (Wave 3) memory-awareness.

extractIntent("can you help me fix the hook error?") // -> "hook error"

shared/session-isolation.ts

Session-specific state file paths so multiple terminals don't collide. ID priority: explicit arg → CLAUDE_SESSION_ID → hostname+PID fallback.

getSessionStatePath("ralph-state") // $TEMP/claude-ralph-state-<sid>.json

shared/db-utils-pg.ts

PostgreSQL coordination layer (migrated from SQLite). Runs queries via coordination_pg.py. Owns cross-terminal coordination: session registration, file claims, and swarm blackboard messages.

ExportPurpose
getPgConnectionString()resolve DB URL (env priority order)
checkFileClaim() / claimFile()file locking — composite key (file_path, project)
getActiveAgentCountPg()count running agents
queryBroadcasts()swarm-coordination blackboard
Why a shared layer. 107 hooks would otherwise duplicate daemon protocols, score payloads, and session-ID logic 107 times. Centralizing it means a fix to (say) the Braintrust fail-open contract lands once and every emitter inherits it. The trade-off: a regression in a shared module is a regression everywhere — which is exactly why the emit-invariant audit exists.

09 · Under the hooks

From idea to a live hook
in six steps.

Hooks are TypeScript in src/, compiled by esbuild to dist/*.mjs, registered in settings.json, tested with vitest (not jest), and synced to ~/.claude/. Skipping the build or the registration is the #1 reason a hook "silently doesn't run".

scaffold → implement → build → register → test → sync
# 3 · build (src → dist via esbuild) cd .claude/hooks && npm run build # → dist/<name>.mjs # 5 · test (vitest, NOT jest — pass session_id!) npx vitest run src/__tests__/<name>.test.ts # 6 · sync to active bash scripts/sync-to-active.sh

Architecture notes

  • TypeScript in src/ → esbuild → dist/*.mjs
  • Test framework: vitest, never jest (import type breaks jest)
  • settings.json is NOT auto-synced — update repo + ~/.claude/
  • Inject pattern: PostToolUse additionalContext
  • Block pattern: PreToolUse permissionDecision: deny
  • Always pass session_id in tests — else PID-based IDs break state matching

Sync seam

A git post-commit hook auto-syncs continuous-claude/ → ~/.claude/ in the background. hooks/src, rules, agents, skills, and (now) dist all forward-sync; settings.json, CLAUDE.md, and RULES.md stay intentionally local.
