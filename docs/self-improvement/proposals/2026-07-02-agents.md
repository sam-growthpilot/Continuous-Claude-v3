# Agents — Next-Evolution Proposal (2026-07-02)

## 1. Where CCv3 is today

**Portfolio.** 36 markdown agent definitions in `.claude/agents/` (counted 2026-07-02), each with frontmatter `name` / `description` / `model` / `tools` (`.claude/agents/scout.md:1-6`). 16 companion `.json` files are an obsolete Agentica-schema duplicate layer that is never executed (D7c-01, `docs/system-update/CURRENT-STATE.md:37`, and confirmed by inspecting `scout.json` — it embeds a stale copy of the same prompt). Agent activity is dominated by the review pipeline: codex-adversary + critic + plan-reviewer ≈ 50% of all spawns, and **30 of 36 agents show no recorded activity** (`CURRENT-STATE.md:37`).

**Routing/selection.** Entirely prompt-level and fragmented across four surfaces: the agent table in `CLAUDE.md` ("Agent Ecosystem"), the pattern-detection table in `.claude/rules/proactive-delegation.md`, hard overrides like `.claude/rules/use-scout-not-explore.md`, and the native description-based automatic delegation the platform performs from each agent's `description` field (https://code.claude.com/docs/en/sub-agents, fetched 2026-07-02). There is no learned or telemetry-informed router, and the 30/36-inactive stat means the routing surface advertises a portfolio the orchestrator mostly ignores.

**Orchestration patterns.** Documented and reasonably rich: maestro supports pipeline / swarm / hierarchical / generator-critic / jury (`docs/agents/README.md:29-52`); Ralph does bounded delegated implementation; the `parallel-agents` skill and the "N parallel sparks, one file each" rule (`proactive-delegation.md` → Spark Scope Limits) encode fan-out discipline. Cost-gating exists as prose ("Don't Over-Delegate", `proactive-delegation.md`).

**Context isolation & handoff.** Isolation is the native per-subagent context window. Handoff back to the orchestrator is a **free-text final message** plus the convention `.claude/cache/agents/<name>/latest-output.md` (`CLAUDE.md` → Agent Ecosystem) and handoff docs in `thoughts/shared/handoffs/`. The one structured-return precedent is Ralph's required `ralph_status` JSON (`CLAUDE.md` → Workflow Orchestrators). The context-bus symbol layer that was designed to carry cross-agent findings is **write-dead** — `SubagentStop` has zero registrations, so `proposed_bus_updates` are silently dropped (`CURRENT-STATE.md:12,46`; backlog ST-01).

**Verification of agent work.** Strong on cross-model review (codex-adversary as a distinct input source, `.claude/rules/codex-adversarial.md`) and on the prose rule "don't trust agent claims — run tests" (`RULES.md` → External Verification), plus the mechanical post-spark emit audit (`proactive-delegation.md` → Post-Spark Verification). Weak on instrumentation: the entire 12-hook spawn-side guard/verify chain never fires (matcher `'Agent'` vs live `'Task'`, QW-04 unshipped — `CURRENT-STATE.md:11`), and the `agent_task_success` Braintrust score is dead for the same reason (`CURRENT-STATE.md:40`).

**Known limitations already on the books:** subagents are memory-blind (0 of 281 recall events from the agent layer, `CURRENT-STATE.md:35`; ST-05 shipped, ST-10 pending); subagents share the parent `session_id` so the file-claims lock is blind to intra-session fan-out (ST-02 `agent_id` extension + MS-01, `docs/system-update/BACKLOG.md:59,82`); DEL-11 already earmarks doc-coupled agents for operator-confirmed deletion (`BACKLOG.md:105`).

## 2. Frontier scan

All URLs below were fetched/verified directly on 2026-07-02 unless marked otherwise.

1. **Anthropic — How we built our multi-agent research system** (Jun 2025, https://www.anthropic.com/engineering/multi-agent-research-system). Orchestrator-worker with parallel subagents beat single-agent Opus 4 by **90.2%** on their internal research eval — but multi-agent systems use **~15× the tokens of chat**, and "token usage by itself explains 80% of the variance" in performance. Multi-agent wins on breadth-first parallelizable work and **underperforms on tasks with heavy interdependencies, like most coding**. Prompting lessons: explicit effort-scaling ("simple = 1 agent, 3-10 tool calls; comparisons = 2-4 subagents, 10-15 calls each"), and detailed task descriptions with objectives, output formats, and boundaries to prevent duplication. Evaluation: a single LLM judge scoring 0.0–1.0 + pass/fail on a rubric (factual accuracy, citation accuracy, completeness, source quality, tool efficiency).
2. **Cognition — Don't Build Multi-Agents** (Jun 2025, https://cognition.com/blog/dont-build-multi-agents). The counter-position: parallel subagents make conflicting implicit decisions that can't be cleanly reconciled. Principles: "share context, and share full agent traces, not just individual messages" and "actions carry implicit decisions, and conflicting decisions carry bad results." For long tasks, use a dedicated compression LLM over agent history instead of fan-out.
3. **Claude Agent SDK — building agents** (Sep 2025, https://claude.com/blog/building-agents-with-the-claude-agent-sdk). Names exactly two reasons to use subagents: parallelization, and context management via "isolated context windows" where subagents "send relevant information back to the orchestrator, rather than their full context." Ships automatic context compaction when the window nears its limit.
4. **Anthropic — Agent Skills** (Oct 2025, https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills). Three-tier progressive disclosure (metadata pre-loaded → SKILL.md on relevance → linked files on demand) as the mechanism for **specialization without spawning**: inject specialist procedure into the *current* agent just-in-time rather than "building fragmented, custom-designed agents for each use case."
5. **Claude Code sub-agents docs** (fetched 2026-07-02, https://code.claude.com/docs/en/sub-agents). Delegation is driven by each subagent's `description`; the doc's stated bar for *defining* a custom subagent is "when you keep spawning the same kind of worker with the same instructions." The platform has also grown adjacent primitives — background agents (`/agent-view`) and **agent teams** (sessions that communicate with each other) — beyond single-session Task fan-out.
6. **OpenAI Agents SDK — handoffs vs agents-as-tools** (2025, https://openai.github.io/openai-agents-python/handoffs/ and https://openai.github.io/openai-agents-python/multi_agent/). Codifies the two canonical control-flow idioms: *handoff* (peer transfer — the specialist takes over the conversation) vs *agent-as-tool* (central orchestrator retains control and calls specialists). CCv3 uses only the second. [Oracle-verified via official docs; not re-fetched.]
7. **RouteLLM** (arXiv 2406.18665, verified abstract 2026-07-02, https://arxiv.org/abs/2406.18665). Lightweight routers trained on human preference data dynamically pick stronger-vs-weaker models per query, cutting cost "by over 2 times in certain cases" without quality loss, and transfer across model pairs. The reference point for *learned* routing as the alternative to LLM-judgment routing.
8. **Agent-as-a-Judge** (arXiv 2410.10934, verified abstract 2026-07-02, https://arxiv.org/abs/2410.10934). Extends LLM-as-a-judge with agentic features that give "intermediate feedback for the entire task-solving process" — i.e. grade the trajectory, not just the final answer. On the DevAI benchmark (55 AI-dev tasks, 365 hierarchical requirements) it "dramatically outperforms LLM-as-a-Judge and is as reliable as our human evaluation baseline."
9. **Framework handoff models — LangGraph / CrewAI / AutoGen** (secondary comparison, https://www.datacamp.com/tutorial/crewai-vs-langgraph-vs-autogen). Three live answers to orchestrator↔worker context: shared graph state with merge reducers (LangGraph), scoped role memory store (CrewAI), shared transcript + aggressive pruning (AutoGen). Directional only — [Speculation] on the exact per-framework mechanics beyond what the comparison states.
10. **Synthesis across 1–3** (oracle scan, 2026-07-02): the 2025 "do vs don't build multi-agents" split has largely collapsed into a hybrid — one agent *owns* context engineering and spawns isolated workers only for well-scoped, parallelizable subtasks; the open hard problem is the handoff/reconciliation boundary, and structured returns from workers are becoming the norm over free text.

## 4. Recommendations

**R1 — Curate the portfolio: shrink 36 advertised agents to the active core, convert prompt-only specialists to skills, delete the 16 dead `.json` twins. ADOPT.**
The telemetry (30/36 inactive, `CURRENT-STATE.md:37`) and the platform's own definition bar ("define a custom subagent when you keep spawning the same kind of worker") both say the portfolio is over-built. Agents whose only specialization is a prompt persona with read-only tools (e.g. the review-family variants judge/surveyor/liaison vs critic, or doc-coupled agents already flagged DEL-11) are what Agent Skills' progressive disclosure is *for* — specialization without paying a spawn + description-table slot (https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills). Keep genuinely isolation-earning agents (scout, oracle, kraken, spark, critic, codex-adversary, debug-agent/sleuth, arbiter/atlas, maestro, scribe, deployer). This also *improves routing accuracy for free*: native description-matching over ~14 sharp descriptions beats matching over 36 overlapping ones. [Speculation on the exact keep-list — the cut is operator-confirmed per DEL-11's existing posture.] Archive, don't delete (destructive-commands rule).

**R2 — Structured return contracts for the core agents. ADOPT.**
The frontier's convergent lesson — subagents are filters that return distilled, structured results, and vague task/return specs cause duplication and gaps (Anthropic multi-agent post; Cognition's conflicting-implicit-decisions failure mode) — while CCv3's workers return free text that the orchestrator re-parses by convention. We already have the precedent (`ralph_status` JSON required from Ralph agents) and the native mechanism (the Workflow tool's schema-forced StructuredOutput). Extend the per-agent `.md` templates with a small required return block per family: reviewers → findings array (file/line/severity/verdict), scouts → facts array with `file:line` evidence, implementers → files-changed + verification-evidence + status. The orchestrator-side rules (`proactive-delegation.md`) then check presence, not prose. Effort S–M, immediate reliability win.

**R3 — Instrumented per-spawn outcome grading (rubric'd, trajectory-aware). ADOPT (gated on QW-04 / the 2026-07-01 hooks proposal R1).**
Anthropic's production answer is a single LLM judge with a 0.0–1.0 rubric + pass/fail; Agent-as-a-Judge shows trajectory-level grading "dramatically outperforms" final-answer-only judging (arXiv 2410.10934). CCv3 built this muscle for reviews only. Once the subagent lifecycle events fire (QW-04 → or better, the native `SubagentStart`/`SubagentStop` re-target from yesterday's hooks proposal R1), revive `agent_task_success` and grade each spawn against a 3-field rubric (task satisfied / evidence present / return-contract honored per R2). Cheap deterministic version first (did the structured return validate? did verification evidence exist?); LLM-judge only where deterministic checks can't decide. Feeds SG-04's metrics directly.

**R4 — Learned agent router (RouteLLM-style). SKIP.**
Preference-data routers need query volume and labels a single-operator harness doesn't generate; RouteLLM's win is cost-routing between model tiers, which CCv3 already handles by per-agent `model` frontmatter and the no-haiku rule. R1's curation attacks the actual routing problem (description dilution) at ~zero cost.

**R5 — Peer handoffs / native agent teams. WATCH.**
The OpenAI handoff idiom and Claude Code's agent-teams primitive are real, but our dominant workload is interdependence-heavy coding — exactly where Anthropic's own post says multi-agent underperforms, and where Cognition's conflicting-decisions critique bites hardest. Revisit if/when the MS-* multi-session arc lands and cross-session coordination (Postgres substrate) is identity-reliable (ST-02).

**R6 — Subagent memory recall. SKIP (as new work) — already tracked.**
The frontier confirms the direction (scoped worker memory), but ST-05 (shipped) + ST-10 already own this arc. Adding a parallel proposal would duplicate the backlog.

## 6. Benefits

- **Cheaper + more accurate delegation.** A curated portfolio cuts the always-in-context agent table and makes native description-routing sharper; the 15×-token finding says spawns should be reserved for isolation-earning work — R1 institutionalizes that instead of leaving it to prose.
- **Fewer silent agent failures.** Structured returns (R2) turn "agent says done" into a checkable artifact — the exact failure class RULES.md's External Verification rule exists to catch, but mechanized.
- **A real quality signal per spawn.** R3 gives the user the first per-agent success metric (today: zero — the emit is dead), so the *next* portfolio curation round is data-driven rather than archaeology.
- **Less maintenance surface.** 16 dead .json files, ~20 archived personas, and 4 routing surfaces collapsing toward 2 (frontmatter descriptions + one delegation rule).
