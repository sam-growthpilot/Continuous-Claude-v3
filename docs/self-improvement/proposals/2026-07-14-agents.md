# Agents — Next-Evolution Proposal (2026-07-14)

## 1. Where CCv3 is today

Verified against the repo (not the dated snapshot):

- **39 agent definitions**, one `.md` each with YAML frontmatter (`name`, `description`, `model`, `tools`) in `.claude/agents/` (verified: `ls .claude/agents/*.md` → 39; `docs/system-update/CURRENT-STATE.md:37` still says "36", pre-dating the 4 cross-model agents codex/grok × worker/adversary). Selection guidance lives in `docs/agents/README.md` (decision trees) and the `proactive-delegation.md` rule.
- **Context isolation = "agent-as-tool".** The orchestrator (main model) spawns a subagent via the Task tool; the subagent runs in its own fresh context window and returns only its final message to the parent, keeping the orchestrator context clean. This is the design intent throughout (`docs/agents/README.md:29-52`, the whole "delegate to keep main context clean" premise in `.claude/rules/proactive-delegation.md`). CCv3 has **no "handoff"** pattern (full-conversation transfer to a specialist) — every agent is a helper the orchestrator calls and stays responsible for.
- **Explicit two-tier cost routing.** Every predefined agent carries an explicit `model: opus | sonnet` (never omit/inherit, never haiku) per `.claude/rules/agent-model-selection.md`. Tiering is by *judgment density*: verified live tiers — `kraken: sonnet`, `scout: sonnet`, `oracle: sonnet`, `spark: sonnet`, `critic: opus`, `maestro: opus` (post-PR#17 retier). **Reasoning effort is a single GLOBAL `effortLevel`** in `~/.claude/settings.json`, not per-agent (`.claude/rules/agent-model-selection.md`).
- **Spawn-side guard chain is now LIVE.** The `Agent`→`Task` matcher flip (BACKLOG `QW-04`) has shipped: both `.claude/settings.json:21,316` and `~/.claude/settings.json` register `agent-model-guard` (PreToolUse:Task), `agent-error-capture` + `agent-verification` (PostToolUse:Task). This contradicts the still-live claim in `docs/system-update/CURRENT-STATE.md:11,37` that "the entire agent safety + verification chain never fires" — that snapshot is stale for this component.
- **Post-spawn verification is informational only.** `agent-verification.ts:15-17` states plainly: "This is informational only (warnings), not blocking. PostToolUse cannot block, only inject context." It checks file-existence for implementation agents (`kraken`, `spark`, `scribe`, `herald`).

## 2. Frontier scan

- **Anthropic, "How we built our multi-agent research system"** — orchestrator-worker with parallel subagents, each with its own context window for compression. Hard cost figures: "agents typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats"; token usage explained ~80% of performance variance. Multi-agent won breadth-first parallel tasks (+90.2% on their internal research eval vs single-agent Opus) but they warn "most coding tasks involve fewer truly parallelizable tasks than research, and LLM agents are not yet great at coordinating and delegating to other agents in real time." Subagent prompting: each needs "an objective, an output format, guidance on the tools and sources to use, and clear task boundaries," plus explicit *scaling rules* mapping query complexity to effort budgets (1 agent / 3-10 calls for simple; 10+ subagents for complex). https://www.anthropic.com/engineering/multi-agent-research-system
- **Cognition, "Don't Build Multi-Agents"** — the counterweight. Two principles: (1) "Share context, and share full agent traces, not just individual messages"; (2) "Actions carry implicit decisions, and conflicting decisions carry bad results." Parallel subagents that don't see each other's full context make conflicting assumptions (the Flappy-Bird example). Recommended architecture: single-threaded linear agents, and for long context, a dedicated LLM "whose key purpose is to compress a history of actions & conversation into key details, events, and decisions." https://cognition.com/blog/dont-build-multi-agents
- **Claude Code / Agent SDK — Subagents** — the native feature does **automatic delegation off the `description` field** ("the description is not documentation, it is the trigger"); context isolation is explicit ("a subagent's context window starts fresh… the only channel from parent to subagent is the Agent tool's prompt string… only its final message returns to the parent"). https://code.claude.com/docs/en/agent-sdk/subagents
- **OpenAI Agents SDK — Orchestration & Handoffs** — codifies two routing primitives: **handoffs** (transfer the full conversation to a specialist who "owns the next response") vs **agents-as-tools** (`agent.as_tool()`, the caller "stays responsible for the final answer and calls specialists as helpers"). https://developers.openai.com/api/docs/guides/agents/orchestration · https://openai.github.io/openai-agents-python/handoffs/
- **LangGraph supervisor** — treats agents as nodes in a graph; conditional edges route on arbitrary *state* (not just conversation content) and can split into parallel branches — the "complex branching / state-based routing" end of the spectrum. https://reference.langchain.com/python/langgraph-supervisor
- **τ-bench (Yao, Shinn, Razavi, Narasimhan, arXiv 2406.12045, Jun 2024)** — a tool-agent-user benchmark whose contribution is a **reliability** metric (pass^k): not "can the agent do it once" but "can it do it consistently over k trials." Reported that strong agents drop to ~25% when the same task is repeated 8×. Anthropic model cards now report pass^k. https://arxiv.org/abs/2406.12045

## 3. Gap analysis

| Dimension | Frontier position | CCv3 today | Standing |
|-----------|-------------------|------------|----------|
| **Context isolation** | Subagent own-context, only final message returns (Anthropic, Claude Code docs) | Exactly this — agent-as-tool | **Ahead / even** |
| **Cost routing per agent** | Cheap models for mechanical, expensive for judgment | Explicit two-tier `opus/sonnet` by judgment density | **Ahead** |

| **Routing / selection** | Description-field auto-delegation (Claude Code) or supervisor/state router (LangGraph); Anthropic uses orchestrator *scaling rules* | Manual, rule-driven decision trees; no explicit scaling/"go-multi-agent?" rule | **Behind (partial)** |
| **Agent memory** | Subagents get scoped context via prompt; harnesses increasingly feed retrieved memory into workers | Agent layer memory-blind (2/39 recall; 0/281 rows) | **Behind (biggest gap)** |
| **Post-spawn verification** | Reliability-first eval (τ-bench pass^k); external verification of agent claims | `agent-verification` live but informational-only; no `SubagentStop` pass | **Behind (partial)** |
| **Agent count discipline** | Both Anthropic (15× cost) and Cognition warn against unneeded agents | 39 defs, 30/36 cold, 16 dead `.json`, overlapping reviewers | **Behind (dead weight)** |
| **Multi-agent cost awareness** | 15× token multiplier; use only when task value justifies | No explicit gate; `proactive-delegation.md` encourages fan-out | **Behind (missing gate)** |

## 4. Recommendations

- **R1 — Give judgment-dense agents read-side memory recall. ADOPT.** The single biggest, best-evidenced gap: 0/281 sub-agent recall rows means every spawned scout/architect/kraken/debug-agent re-derives what the system already learned. Add a recall step to the highest-value agents (scout, oracle, architect, kraken, debug-agent/sleuth) — read-only, bounded (`--k 3 --text-only`), same pattern `maestro.md`/`wizard.md` already use. Rationale: cheap, closes a measured hole, compounds with the Memory pillar.
- **R2 — Prune the agent roster (dead + overlapping). ADOPT.** Delete the 16 dead `.json` files (already a BACKLOG DEL candidate), and audit the review family (`critic`, `judge`, `surveyor`, `liaison`, `principal-reviewer`, `review-agent`) and cold long-tail for genuine overlap. Both frontier camps agree: more agents ≠ better; Cognition's whole thesis is that unmanaged fan-out *hurts*. Rationale: less selection ambiguity, less context, honest inventory.
- **R3 — Add an explicit "should this be multi-agent?" gate + orchestrator scaling rules. ADOPT.** Encode Anthropic's effort-budget framing into `maestro`/`proactive-delegation.md`: single agent for tightly-coupled/sequential work; fan-out only for breadth-first parallelizable work; name the 15× token cost so fan-out is a deliberate choice. Rationale: directly imports the strongest field lesson (Anthropic cost figure + Cognition caution) at rules cost, not code cost.
- **R4 — Wire a `SubagentStop` pass that does BOTH context-bus writes and structured verification. ADOPT (medium).** `SubagentStop` is currently unregistered; registering it unblocks `ST-01` (the write-dead `focus_symbols`/`recent_findings`) *and* gives a natural home for a firmer post-spawn verification than the informational PostToolUse hook. Rationale: two open gaps, one registration.
- **R5 — Fix `docs/agents/README.md` model-tier drift. ADOPT (trivial).** The README table is inverted vs the live frontmatter; a reader picks the wrong tier. Doc-only.
- **R6 — Per-agent reasoning effort. WATCH.** Already tracked as a follow-up ([[fable-intelligence-and-agent-model-policy-followup]]); the Workflow tool can set per-call `effort` but Task-spawn cannot. Track the SDK surface; don't build custom plumbing yet.
- **R7 — Description-field auto-delegation / learned router. SKIP (for now).** Claude Code supports auto-delegation off `description`, but CCv3's manual rule-driven selection is legible and debuggable for a single-operator harness, and a *learned* router is unjustified overhead at this scale. Revisit only if roster size or mis-routing telemetry warrants it. Better first step is R3 (explicit scaling rules) than a router.
- **R8 — Reliability (pass^k) grading of agents. WATCH.** τ-bench's lesson — measure consistency over k trials, not one pass — is right, but CCv3 has no per-agent eval harness today and Braintrust telemetry is still corr-null-heavy (60.7%, `ST-02`). Track it; revisit after telemetry identity is fixed.

## 5. Integration approach

- **R1 (memory recall in agents):** edit ~5 agent `.md` prompts (`scout`, `oracle`, `architect`, `kraken`, `debug-agent`/`sleuth`) to add a bounded recall preamble mirroring `maestro.md`. Ties to the **Memory** pillar and the FH-02 → **ST-03/ST-10** recall-daemon arc (a warm daemon makes per-agent recall ~136-250ms, cheap enough to spawn-time; `NEXT-SESSION-PLAN.md:54-59`). Effort: low (docs-only edits). Risk: low; recall is read-only. What could go wrong: unsanitized recall injected into a decision surface — reuse the memory-poison sanitization already applied at 2/5 injectors (`CURRENT-STATE.md:52`) so agent recall doesn't reopen that seam.
- **R2 (prune roster):** delete `.claude/agents/*.json` (gate each on `git grep <basename>` per the DEL discipline in `BACKLOG.md:51`); write a one-page overlap audit of the review family. Effort: low-medium. Risk: low (`.json` are unexecuted); the review-family consolidation is judgment-heavy → propose, don't auto-cut.
- **R3 (multi-agent gate + scaling rules):** add a short section to `.claude/rules/proactive-delegation.md` and `maestro.md`. Effort: low (rules). Risk: low. Reference: Anthropic scaling-rule framing.
- **R4 (`SubagentStop`):** register one `SubagentStop` hook in all three settings surfaces; body does (a) apply codegraph `proposed_bus_updates` (closing `ST-01`) and (b) a structured verification summary. Effort: medium (new hook + tests + `audit-braintrust-emits.sh` 4/4). Risk: medium — `SubagentStop` firing semantics on this build are unverified; spike first. Ties to `ST-01`.
- **R5 (README fix):** rewrite the tier table + "Choose the Right Model" section in `docs/agents/README.md` to match live frontmatter. Effort: trivial. Risk: none.

All of R1-R5 are docs/rules/settings scoped — no core code churn — which fits the low-risk, high-leverage "honing" posture the pillar is in.

## 6. Benefits

- **Fewer repeated mistakes / faster agents (R1):** every scout/architect/kraken run starts with the system's own priors instead of a blank slate — the compounding "every conversation builds on the last" premise finally reaches the agent layer, not just the main loop.
- **Cheaper, clearer delegation (R2, R3):** pruning cold/overlapping agents cuts selection ambiguity; an explicit multi-agent gate keeps Dave off the 15× token path unless the task is genuinely breadth-first — real dollar/quota savings on a subscription-metered stack.
- **More trustworthy "done" (R4):** a structured `SubagentStop` verification hardens the informational-only check into something the orchestrator can act on, and simultaneously revives the write-dead symbol bus.
- **No footguns from stale docs (R5):** the README stops steering readers to the wrong (more expensive) model tier.

Net: the agent ecosystem stays architecturally frontier-aligned (its isolation + cost-tier bones are already right) while closing the four concrete holes — memory-blindness, dead weight, soft verification, and undisciplined fan-out — that separate it from the state of the art.
