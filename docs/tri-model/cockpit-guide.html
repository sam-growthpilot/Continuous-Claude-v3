Your tri-model cockpit

You have a three-model crew inside every Claude Code session. This is the flight manual: what each one does, what to say to make things happen, and the moments where the system stops and waits for you.

Rule zero

You only ever talk to Claude

You never open Grok or Codex yourself. You type commands in your Claude Code session; Claude dispatches the right model, verifies its work independently, and brings the result back to you. Each model runs on its own subscription (ChatGPT / X Premium+) — no API bills.

The big-feature flow

Two gates — you hold both keys

Inside a workroom, work moves through fixed phases. Nothing gets built until you approve the plan (Gate 1), and nothing ships until you approve the result (Gate 2). Everything in between runs on the roster.

plan & contractclaude + you→ GATE 1you approve→ build M1…Mngrok→ smoke checkclaude→ review boothcodex→ fix (max 2 rounds)codex→ GATE 2you ship
Why you can trust "done": a milestone only counts as complete when Claude has run the tests itself and written the exit codes into the room. A builder saying "tests passed" is never accepted as evidence.
Your moments

When the system stops and asks you

These are the only interruptions — each exists for a reason. Everything else runs without you.

Before any build run

"Here's the exact command + isolated folder — go?"

Every --implement shows you precisely what will run and where before spending quota. Say yes, or tweak the task.

After any build run

"Here's the diff — apply or discard?"

The single most important control. Nothing reaches your working files until you approve the patch. Discarding costs nothing.

First Grok content run of a session

"This sends repo content to xAI — ok?"

Grok runs ship context to xAI's servers under your account. You confirm once per session for content-bearing runs; prompts are secret-scanned first, and .env files never ship.

Gates 1 & 2

"Approve the contract / approve the ship?"

Plan sign-off before any milestone is built; final sign-off before anything merges. No auto-merge exists anywhere.

After 2 failed fix rounds

"Fix loop exhausted — your call."

The system never thrashes quota in a loop. Two fix rounds, then it blocks and hands you the decision.

Version drift detected

"CLI changed — run /harness-update first."

Grok auto-updates itself. If the live version stops matching the verified pin, building is blocked until the playbook re-verifies the surface.
